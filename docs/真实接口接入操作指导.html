真实接口接入操作指导

api-auto-framework · 面向页面的多账号接口自动化框架 · 生成于 2026-10-14

适用场景：把本框架当前指向的 mock 服务（127.0.0.1:18888/18889）替换为你们真实的业务系统。

结论先行：需要改动的只有 4 类文件，共 6 个阶段。core/、runner/、cases/base_case.py、 core/auth/ 这些一行都不用改——这正是分层设计的兑现点。

全文所有路径均相对 api-auto-framework/ 根目录。

一、先看清框架长什么样

1.1 分层与依赖方向

runner → cases → apis → core → config
（调度）  （编排）  （接口） （内核） （配置）

依赖单向：下层永远不知道上层存在。core/ 不认识任何具体接口，apis/ 不认识任何流程。 因此「换接口」只会波及 apis/，最多再碰 config/。

层 目录 职责 接真实接口时
配置层 config/ 环境参数、账号与鉴权定义、凭据装载 要改（阶段 1-3）
内核层 core/ 请求唯一出口、鉴权注入、凭证托管、变量传递 不改
页面对象层 apis/ 描述「这个页面有哪些接口」，一个接口一个方法 要改（阶段 4）
用例编排层 cases/ 组织业务流程、传数据、写断言 少量改（阶段 5）
调度层 runner/ 装载 → 装配 → 顺序执行 → 汇总 → 退出码 不改

1.2 一次请求的完整数据流

以用例里的一行 self.apply_page.submit_application("标题") 为例：

① cases/*.py        调用页面方法，只有业务语义，没有一行凭证代码
        ↓
② BaseApi.__init__  确定本页面用哪个账号（account 类属性）
                    并执行 self.client = ctx.client(self.principal)
        ↓
③ Context           转发给 SessionFactory（Context 自己不存任何账号状态）
        ↓
④ SessionFactory    这是「账号」与「鉴权」唯一的交汇点：
                    按 (环境, 账号) 从 TokenStore 取凭证缓存
                    ├─ 命中且未过期 → 直接复用
                    └─ 未命中/已过期 → 用账号表里的 login 定义真正登录一次
                    登录时强制走 auth=False 且用该账号自己的 Session，
                    这样 Set-Cookie 才会落进它专属的 CookieJar
        ↓
⑤ HttpClient        所有请求的唯一出口：
                    拼 URL（base_url + prefix + path）
                    → strategy.prepare()（cookie 策略在此回填 CSRF 头）
                    → strategy.apply()（token 类策略在此注入 header/query）
                    → 发请求；401 自动重登一次；5xx / 网络异常按 retries 重试
        ↓
⑥ ApiResponse       统一响应封装，支持点号路径取值 data.items.0.id

三条铁律（core/session_factory.py 顶部原文）：

  1. 一个账号一个 HttpClient，一个 HttpClient 一个 requests.Session —— Cookie 不可能串。
  2. 登录必须发生在该账号自己的 Session 上 —— 用公共 Session 登录是最隐蔽的串号来源。
  3. 作废会话只作废本人 —— 401 重登不波及其它账号。

1.3 最终 URL 是怎么拼出来的

     base_url              prefix                    path
https://api.example.com  +  /api/v1  +  /flow/cases  =  完整 URL
   （环境配置）           （环境配置或页面类）    （页面方法里写的）

prefix 有三态语义，这是接真实接口时最容易踩的坑：

页面类里的写法 含义 结果
不写 prefix 继承环境配置的 api_prefix /api/v1 + /cases → /api/v1/cases
prefix = "" 明确「无前缀」，方法里的 path 即完整业务路径 "" + /flow/changes → /flow/changes
prefix = "/xx" 页面自带前缀，优先级最高，不受环境配置影响 /orders + /x → /orders/x

优先级：类属性 prefix（非 None）> 环境变量 API_PREFIX > 环境 yaml 的 api_prefix。

1.4 文件职责速查

文件 写什么 阶段
config/env/<env>.yaml base_url、超时、重试、api_prefix、账号表路径、是否落盘 1
config/secrets.env 唯一明文凭据（已 gitignore） 2
config/accounts.<env>.yaml 每个账号：怎么登录 + 怎么带鉴权（只写 ${变量名}） 3
apis/*.py 每个页面：account + 每个接口一个方法 4
cases/*.py 业务流程编排与断言 5
suites/*.yaml 声明跑哪些用例、按什么顺序 5
tools/mock_server*.py 本地 mock（真实接口接入后退役） 6

二、接入前必须拿到的 6 项契约

先把这 6 项信息凑齐再动手，能避免 80% 的返工。缺哪一项就去抓一次包（见 §9.1 的探针脚本）。

# 契约要素 用来填哪些配置
1 base_url（含协议与端口） env/<env>.yaml 的 base_url
2 URL 公共前缀（网关路径 / API 版本，如 /api/v1） env/<env>.yaml 的 api_prefix
3 登录接口：method + path + 请求体字段名 账号表的 login.method / login.path / login.json
4 凭证形态：Set-Cookie 还是响应体里的 token 账号表的 auth.type（见 §3 决策表）
5 每个页面由哪个账号操作 页面类的 account
6 每个接口的 method + path + 入参 + 期望状态码 页面方法内部

参考实现：本项目 8 个页面模板的 mock 契约见 README.md 第九节； 账号表的完整写法示例见 config/accounts.session.yaml。

三、鉴权类型决策表

auth.type 的候选值由 core/auth/strategies.py 注册，当前共 7 种。照着「凭证放在哪」选：

现象（抓包看到什么） auth.type 关键配置 备注
登录响应带 Set-Cookie: SESSION=... cookie session_cookie、csrf_cookie、csrf_header、assume_ttl 本框架主用；写操作自动回填 CSRF
Authorization: Bearer <token> bearer header、prefix、token_path、expires_path
自定义头，如 X-Token: <token> header header、prefix header 必填，否则报 ConfigError
?access_token=<token> query key 凭证会进 URL，注意日志与网关缓存
Authorization: Basic <base64> basic username、password、header 不需要登录，直接吃凭据
X-Timestamp + X-Signature signature algorithm、ts_header、header 内置 HMAC 骨架，真实算法差异大时需扩展
完全公开，不带任何凭证 none — 不登录、不注入；收到 401 不会触发重登

token_path 怎么写：它是在登录响应 JSON 里的点号路径，支持列表下标。

登录响应片段 token_path
{"data": {"access_token": "abc"}} data.access_token
{"token": "abc"} token
{"result": {"items": [{"jwt": "abc"}]}} result.items.0.jwt

取值失败会抛 AuthError 并把实际响应前 200 字符打出来，定位很快。

四、六个阶段的操作步骤

阶段 1 · 建立真实环境配置

新增 config/env/staging.yaml（不要改 dev.yaml / session.yaml，保留 mock 环境用于框架自检）：

# 真实环境（非敏感）。敏感凭据一律放 config/secrets.env
base_url: https://api.example.com

timeout: 15          # 真实网络比 localhost 慢，建议 15 起
retries: 2
backoff: 0.5
verify_ssl: true     # ★ 真实环境务必改回 true；mock 才用 false

# 页面 URL 公共前缀：只在这一处定义，页面类共用
api_prefix: /api/v1

# 账号表：真实环境单独一份，不要与 mock 环境的混用
accounts_file: config/accounts.staging.yaml

# 会话落盘 = 明文会话写磁盘。真实环境建议 false
persist_credentials: false

log_level: INFO

验证

python runner/main.py --env staging --list-accounts

期望：打印账号表并把「已支持的鉴权类型」列出来。若报 找不到环境配置 说明文件名拼错 （环境名即文件名，--env staging ↔ config/env/staging.yaml）。

阶段 2 · 填写凭据

改 config/secrets.env（该文件已在 .gitignore，不会进版本库）。

  • 一行一个 KEY=VALUE，不要写 export
  • 值两侧的引号会被自动剥掉
  • 变量名必须匹配 [A-Za-z_][A-Za-z0-9_]*（不能以数字开头、不能带连字符），否则 ${} 不会被替换
  • 想新增账号就新增键，建议按系统命名，别再叫 TEST34_PASSWORD 这种 mock 遗留名

CI 里的做法：同名真实环境变量优先。config/settings.py 用的是 os.environ.setdefault， 所以 CI Secret 不会被本地文件覆盖；反过来说——如果你 shell 里已经存在同名变量，改 secrets.env 不会生效， 排查「明明改了却没变」先查这个。

验证：故意把某个变量删掉再跑，应当得到明确报错而不是静默失败：

[框架级错误] ConfigError: 凭据缺失：环境变量 XXX_PASSWORD 未定义。
请在 config/secrets.env 里补齐，或在 CI 中作为 Secret 注入。

阶段 3 · 定义账号与鉴权

新增 config/accounts.staging.yaml。结构分两段：defaults（公共默认）+ accounts（逐账号覆盖）。

⚠️ 顶层键必须是 accounts:（旧名 roles: 也认，但推荐新名）。 这个键名不是配置项，它硬编码在 config/settings.py:131 的字典查询里——改名字必须改代码。 path 必须用绝对路径（${ROOT} 占位见下），相对路径会拼在 root_dir 上。

# ============================================================
# 真实环境账号注册表
# 绝对不写明文口令，只用 ${VAR} 引用 config/secrets.env
# ============================================================

defaults:
  login:
    method: POST
    path: /api/v1/auth/login        # ★ 相对 base_url 的 path（不含 base_url）
  auth:
    type: cookie
    session_cookie: JSESSIONID      # 按真实系统的 Cookie 名改
    csrf_cookie: csrftoken
    csrf_header: X-CSRFToken
    assume_ttl: 1800

accounts:
  # ---------- 会话 Cookie 型 ----------
  creator:
    role: creator
    description: 流程创建人
    login:
      json:
        username: ${STG_CREATOR_USER}
        password: ${STG_CREATOR_PWD}
        # 真实系统常需要额外字段，按契约加即可：
        # captcha: ""
        # tenant: "default"

  # ---------- Bearer Token 型 ----------
  sre_expert_a:
    role: sre_expert
    description: SRE 专家 A
    login:
      method: POST
      path: /api/v1/oauth/token     # 可覆盖 defaults 的 path
      json:
        client_id: ${STG_SRE_CLIENT_ID}
        client_secret: ${STG_SRE_CLIENT_SECRET}
    auth:
      type: bearer
      header: Authorization
      prefix: "Bearer "
      token_path: data.access_token
      expires_path: data.expires_in

  # ---------- 无凭证 ----------
  anon:
    role: guest
    login: null
    auth:
      type: none

登录请求体：login 段支持三选一，按真实接口选一个即可（同时写多个时按 json → data → params 取第一个）：

场景 写法
JSON body（最常见） json: { username: ..., password: ... }
表单提交 application/x-www-form-urlencoded data: { username: ..., password: ... }
参数拼在 URL 上 params: { ... }
需要额外请求头 headers: { X-Tenant: xxx }

验证

python runner/main.py --env staging --account creator --fresh-token

期望看到 登录账号 creator POST /api/v1/auth/login → 登录成功。失败会明确区分：

  • AuthError: 账号 'creator' 登录失败 HTTP 401: ... → 凭据或字段名不对
  • AuthError: 登录响应中找不到凭证路径 'data.access_token' → token_path 写错
  • ConfigError: 未知鉴权方式 'xxx' → auth.type 拼错

阶段 4 · 改写页面对象（核心工作）

对 apis/ 下每个页面类，只动两处：

替换点 改什么
① account 这个页面实际由哪个账号操作
② 方法内部 path 与入参，换成真实接口的

改造前（mock 模板）

class ApplyPageApi(BaseApi):
    account = "test1"

    def submit_application(self, title, **extra):
        payload = {"title": title, **extra}
        return self.post("/cases", json=self.ctx.interpolate(payload))

改造后（真实接口）

class ApplyPageApi(BaseApi):
    account = "creator"          # ① 换成真实环境的账号名

    def submit_application(self, title, product, priority="P2", **extra):
        """提交问题处理申请。"""
        payload = {                       # ② 字段名按真实契约对齐
            "title": title,
            "product": product,
            "priority": priority,
            **extra,
        }
        return self.post("/cases", json=self.ctx.interpolate(payload))

契约没对齐时的常见形态对照

契约形态 页面方法写法
查询参数 return self.get("/cases", params=self.ctx.interpolate(params))
路径参数 return self.post(self.ctx.interpolate(f"/cases/{case_id}/expert-review"))
表单提交 return self.post("/cases", data=payload)
文件上传 return self.post("/attachments", files={"file": open(path, "rb")})
需要幂等键 return self.post("/cases", json=payload, headers={"Idempotency-Key": key})
无需鉴权的公开接口 return self.get("/public/notice", auth=False)

完成后跑一次冒烟：

python runner/main.py --env staging --suite all_pages

阶段 5 · 编排用例与套件

用例层通常不用改。 它只认「页面对象 + 方法名」，不认路径、不认账号、不认凭证。 只有当接口的状态码或响应结构变了，才需要同步改断言。

改断言（cases/all_pages_case.py 等）：

# 真实接口返回 200 而不是 201
self.check("① 申请页面 · 提交申请", created, 200,
           expect=field("data.status", "applied"))

# 真实系统的字段路径不同时，改 field 的第一个参数即可
self.check("回查单据详情", detail, 200, expect=field("result.caseNo"))

新增套件：在 suites/ 下建 <name>.yaml：

name: 真实环境冒烟
description: 覆盖 8 个页面的主链路
cases:
  - cases.all_pages_case:AllPagesFlowCase

覆盖清单（建议按此顺序推进，每步都可独立验证）：

待办 文件 改完怎么验
8 个页面类替换 apis/*_page.py --env staging --suite all_pages
账号与角色对齐 config/accounts.staging.yaml --env staging --suite account_roles（需同步改 EXPECTED_ROLES）
多账号隔离仍成立 cases/multi_account_flow_case.py --env staging --suite multi_account
补齐业务用例 新建 cases/*_case.py + suites/*.yaml 对应套件全绿

cases/account_roles_case.py 里的 EXPECTED_ROLES 是硬编码的 mock 账号名 （test1/test34/test38/test666）。接真实环境时，要么改这个常量，要么把这个用例从真实环境套件里移除。

五、接口对接规范（硬性约定）

页面方法是「接口的声明」，写得一致才有可维护性。以下 8 条请当成 lint 规则执行。

① 一个页面一个文件、一个接口一个方法。 文件 xxx_page.py / 类 XxxPageApi；新增页面后要在 apis/__init__.py 里导出。

② 方法体里禁止任何凭证代码。 不许出现 headers["Authorization"]、不许自己 requests.post、不许读 secrets.env。 鉴权在 BaseApi.__init__ 的那一行就已经挂好了。

③ 路径只写相对路径。 不要写 https://、不要重复 base_url、不要重复页面前缀。 前缀要么继承环境配置（不写 prefix），要么由类属性声明，不要在方法里拼。

④ 需要临时换账号用 as_account()，不要改全局状态。

return self.as_account("ops_admin").post(f"/cart/orders/{order_id}/approve")

它返回新实例，不会污染当前对象的默认账号。

⑤ 入参一律过 ctx.interpolate()。 这样 ${case_id} 这类跨步骤变量才能被替换：

return self.post(self.ctx.interpolate(f"/cases/{case_id}/expert-review"),
                 json=self.ctx.interpolate(payload))

⑥ 统一返回 ApiResponse，不要在页面层做断言。 页面方法只负责「发请求 + 返回响应」；断言属于用例层（self.check(...)）。 页面层做了断言，报告里就看不到步骤粒度的失败原因。

⑦ 写操作要显式体现副作用。 方法名用动词（submit_x / approve / deploy），并在 docstring 里写清前置状态约束 （例如「必须先通过评审，否则 409」），方便用例层设计反例。

⑧ 不臆造权限矩阵。 mock 侧只做了「已登录 + 阶段顺序」两道门禁。你们真实系统的角色权限确定后， 再往用例里补越权反例（403/409），不要在页面层做角色判断。

六、用例编写规范

执行顺序有两套规则，互不冲突：

层级 依据
用例之间 suites/*.yaml 里 cases: 列表的顺序
用例内部 方法名字典序 → 用 test_01_ / test_02_ 前缀控制

生命周期：setup_case() → test_01_* → … → teardown_case()。 单个步骤失败不中断整条流程，所有结果都进 CaseResult，一次运行看到全貌。

取页面对象用带缓存的 self.api()（同类 + 同账号只构造一次）：

def setup_case(self) -> None:
    self.shop_a = self.api(ShopApi)                        # 用页面类默认账号
    self.shop_b = self.api(ShopApi, account="buyer_b")     # 换成账号 B
    self.admin  = self.api(ShopApi, account="ops_admin")

跨步骤传数据用 ctx.set / ${var}：

case_id = created.get("data.id")
self.ctx.set("case_id", case_id)                  # 存

记录结果有两种，按是否走 HTTP 分开用：

self.check("步骤名", response, 200, expect=field("data.status", "applied"))  # 有请求
self.mark("步骤名", 条件, "说明文本")                                        # 无请求

内置断言（core/assertions.py）：status(code)、ok()、field(path, expected, exists=...)、 faster_than(ms)、all_of(*checks)。field 不传 expected 时表示「存在且非空」。

teardown_case() 目前 5 个用例都没覆写 —— 真实环境必须补上，否则会持续产生脏数据。 真实系统的清理通常是软删除，建议约定：

def teardown_case(self) -> None:
    case_id = self.ctx.get("case_id")
    if case_id:
        resp = self.apply_page.client.delete(f"/api/v1/cases/{case_id}")
        self.mark("清理测试单据", resp.status_code in (200, 204, 404),
                  f"HTTP {resp.status_code}")

七、注意事项与陷阱

以下每条都是本项目实际踩过或实测确认存在的问题，按真实环境接入的影响度排序。

1. 前缀漏配 = 大面积 404。 环境文件里没写 api_prefix 时值为空，未声明 prefix 的页面会直接拼出 /cases。 启动日志会打印当前生效前缀，为空时给 WARNING。看到 WARNING 先别跑用例。

2. Git Bash 下用环境变量传前缀会被改写。 API_PREFIX=/api/v1 python ... 里 MSYS 会把 /api/v1 当路径转换。需要 MSYS_NO_PATHCONV=1，或干脆改配置文件。

3. 环境与套件是隐式耦合的，没有预检。 OrderApi / UserApi / ProductApi 声明的是 mock 环境的账号（merchant/admin/guest）， 8 个 *_page.py 声明的是另一批（test1/test34…）。若拿真实环境账号表去跑 dev 套件， 会在第一次构造页面对象时抛 RoleNotDefined，而不是启动时。接真实环境时请一个环境配一份账号表。

4. 同角色不同账号必须用不同的账号名。 buyer_a / buyer_b 这类「同角色多账号」是四眼原则（创建人不能自己评审）唯一可测的前提。 合并成「一个账号多角色」会让双人复核规则再也无法构造反例。

5. 切账号最容易漏的一步是 CSRF。 CSRF token 与 session 绑定，换账号必须跟着换。框架在 CookieAuth.prepare() 里自动回填， 但如果你手写 auth=False 绕过它（像 multi_account_flow_case.py:121 那样），就必须自己保证配对。

6. persist_credentials: true = 明文会话落盘。 会话模式下落盘就是把 Cookie 写进 runtime/credentials.<env>.json。真实环境务必设 false。

7. 报告会写凭证前 8 位。 runner/main.py 的 build_report() 会把 token 前 8 字符写进 JSON 报告 （cookie 类则写 Cookie 名列表，不写值）。真实环境的报告若会外发，需要处理这一处。

8. 401 重登只对「本来就要凭证」的账号生效。 none / basic 收到 401 不会重登（重登也没意义），这是刻意设计，不是 bug。

9. --fresh-token 的语义。 不带这个参数时，ctx.login() 默认复用缓存；只有 --fresh-token 才强制重新登录。 排查「凭据改了没生效」时，先加这个参数排除缓存干扰。

10. 凭证变量优先级的反直觉点。 settings.py 用 os.environ.setdefault，所以真实环境变量优先于 config/secrets.env。 本地改文件不生效时，先 echo $XXX_PASSWORD 看看 shell 里是不是已经有一份。

11. verify_ssl 默认值是 false。 settings.py 里 data.get("verify_ssl", False)。真实环境请在环境 yaml 里显式写 verify_ssl: true。

12. 没有重试上限保护的自定义脚本不要进 CI。 框架自身的重试只覆盖网络异常与 5xx，且 retries 是有限次；不要在页面方法里再套循环重试。

9.1 抓真实接口契约的探针脚本

接真实接口前，先用它把「登录响应的形状」和「凭证放在哪」确认下来（不依赖框架）。

保存为 tools/probe_login.py，然后 python tools/probe_login.py：

"""真实接口契约探针：看清登录响应的结构、Cookie 与状态码。

只用于前期调研，看清结构后请把结论写进 config/accounts.<env>.yaml。
"""
from __future__ import annotations

import json
import os

import requests

BASE = os.environ["PROBE_BASE_URL"]          # 例：https://api.example.com
PATH = os.environ.get("PROBE_LOGIN_PATH", "/auth/login")
USER = os.environ["PROBE_USERNAME"]
PWD = os.environ["PROBE_PASSWORD"]

with requests.Session() as s:
    resp = s.post(f"{BASE.rstrip('/')}{PATH}",
                  json={"username": USER, "password": PWD},
                  timeout=15, verify=True)

print("状态码:", resp.status_code)
print("--- 响应 Cookie（决定 auth.type=cookie 还是 token 类）---")
for c in s.cookies:
    print(f"  {c.name} = <{len(c.value)} 字符>  domain={c.domain}")
print("--- 关键响应头 ---")
for k in ("Content-Type", "Set-Cookie", "X-Request-Id"):
    if k in resp.headers:
        print(f"  {k}: {resp.headers[k][:120]}")
print("--- 响应体结构（已脱敏：只打印路径与类型）---")


def shape(node, prefix=""):
    if isinstance(node, dict):
        for k, v in node.items():
            shape(v, f"{prefix}{k}.")
    elif isinstance(node, list):
        print(f"  {prefix[:-1]}: list[{len(node)}]")
        if node:
            shape(node[0], f"{prefix}0.")
    else:
        print(f"  {prefix[:-1]}: {type(node).__name__} (长度 {len(str(node))})")


try:
    shape(resp.json())
except ValueError:
    print(f"  非 JSON 响应，前 200 字符: {resp.text[:200]}")

print("\n对照 config/accounts.<env>.yaml：")
print("  有 Set-Cookie  → auth.type: cookie")
print("  响应体里有 token → auth.type: bearer / header / query，token_path 按上面打印的路径填")
