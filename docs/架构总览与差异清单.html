一、架构总览

五层单向依赖，配置层被内核层读取，横切件挂在两侧。依赖方向不可逆：上层能调下层，下层不知道上层的存在 —— 这是「换掉真实接口时用例层不用改」的结构基础。

双环境 · 双账号表（这是全项目最容易踩坑的地方）

项目里同时存在两套互不相通的账号体系，各自服务一个 mock 服务，且没有任何代码校验「当前套件所需的账号是否在当前环境里存在」：

五、已经做得对的地方（别改）

  • 请求出口唯一：所有 HTTP 都走 HttpClient.request，401 自愈、重试、超时有唯一收口点。
  • 串号的物理防线：一账号一 requests.Session，CookieJar 不共享；登录也强制走本账号 Session（session_factory.py:188）。
  • 登录请求 auth=False：避免"取凭证 → 401 → 重登 → 再取凭证"的死循环（http_client.py:125-134）。
  • 兼容别名是有意为之：role→account 改名没有破坏任何旧调用，说明抽象层选对了位置。
  • 前缀三态语义清晰：None / "" / "/xx" 三种取值有文档、有实测、有启动告警（base_api.py:29-33、main.py:158-165）。
  • 凭据与配置分离：YAML 只写 ${VAR}，os.environ.setdefault 保证 CI Secret 优先（settings.py:46）。
